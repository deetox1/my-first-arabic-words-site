Privacy policy

Last updated: 13 October 2026

This policy describes the My First Arabic Words website and the proposed, narrowly scoped Pinterest integration used to market the existing Arabic–French educational printable bundle. The resources are intended for adults choosing learning materials for children; the Pinterest marketing tool is for adult account holders, not for children.

Current status and important distinction. The public website is a static GitHub Pages site and does not itself connect to Pinterest or contain a server/database for Pinterest data. Pinterest authorization has been connected in the launch workflow, but the exact scopes currently granted have not been independently confirmed here. Pinterest has reported that production Pin creation requires Standard API access; production publishing is not enabled by this website. The categories below describe data the integration may access only if the corresponding Pinterest permission is granted and the API makes that data available—not a claim that all such data is currently being collected.

1. Information the website handles

The public website presents product information and links to the existing Ko-fi listing and a free sample. It has no website account registration, checkout form, contact form, or intentionally installed advertising pixel or third-party analytics script. GitHub Pages and normal network infrastructure may process technical request data such as IP address, browser information, and server/security logs under their own policies. If you follow an external link, that provider's privacy terms apply.

2. Pinterest data the integration may access

After an account owner authorizes the app, and only within approved scopes and API availability, the integration may process:

  • Basic account/profile details: Pinterest user ID, username, account type, and other basic profile fields needed to identify the connected account and show the owner which account is in use.
  • Boards: board IDs, titles, descriptions, privacy/visibility status, and other fields returned by Pinterest, to select the existing “Arabic Learning at Home | Printables” board and confirm where approved content belongs.
  • Pins: Pin IDs, titles/descriptions, destination links, image/media URLs, board association, publication status, and related metadata, to review the business's own promotional content and avoid duplicates.
  • Analytics, if separately available and authorized: performance metrics Pinterest makes available, such as impressions, saves, outbound clicks, or other Pin/board insights, to evaluate which educational-printable promotions are useful.
  • Publishing actions, only with write permission: content and image data supplied for a Pin, plus the selected destination board, if the account owner asks the tool to create or manage a Pin. Read permission alone does not authorize writing.

The integration is not designed to access Pinterest passwords, private messages, or unrelated personal content. It requests no permission merely because that permission exists; actual access is limited by the scopes shown in Pinterest's authorization/consent flow and by Pinterest's approval and API rules. If a scope is not granted, the related data or action is unavailable.

3. Why the data is used

Data is used only to identify the authorized business account, read the chosen board and relevant Pins, prepare or publish user-approved promotional Pins for the existing printable product, and review available performance metrics. It is not used to build advertising profiles, sell personal data, or market unrelated products. Publishing should occur only after the account owner selects or approves the content and destination.

4. How data is handled and stored

The website repository itself does not store Pinterest access tokens or Pinterest API responses. No persistent Pinterest-data database or long-term analytics store is configured in this static website. During an authorized integration session, API responses may be processed to complete the requested action and display the result. The external authorization/integration provider and Pinterest may process connection credentials, request metadata, and logs under their own privacy and security policies. We do not publish access tokens, passwords, or private account data in the public repository.

If a future version adds persistent storage, background scheduling, or additional data categories, this policy should be updated before that feature is enabled to explain the new data, purpose, and retention period.

5. Retention

The static website has no configured Pinterest-data database, so it has no website-defined retention period for Pinterest profile, Pin, Board, or analytics data. Data returned during an integration session is used for that session's task; any retention of authorization tokens, service logs, or operational records by Pinterest or the connected integration provider is governed by those providers' own policies and settings. Revoke the connection when it is no longer needed. We do not claim to be able to delete records held by Pinterest or another provider.

6. Sharing

Data is exchanged with Pinterest to perform the authorized API request and may pass through the integration/authorization provider used to connect the account. Website hosting providers may process routine technical logs. We do not sell Pinterest data or share it with advertising networks. We do not disclose it to unrelated third parties except where necessary to provide the requested integration, comply with law, or protect security.

7. Security

Access should be limited to the minimum necessary permissions. Authentication is handled through the relevant authorization flow rather than by asking you to give this website your Pinterest password. The public website is served over HTTPS by GitHub Pages. No internet service can guarantee absolute security; protect your Pinterest account, review the permissions requested during authorization, and do not share access tokens.

8. Your choices and rights

  • You can decline authorization or grant only the scopes you are comfortable with.
  • You can revoke the app's access from your Pinterest account's connected-app/security settings. Revocation prevents future API access after Pinterest applies it; it does not automatically erase records retained by Pinterest or the integration provider.
  • You may request access to, correction of, or deletion of any personal data the app itself stores. At present, no persistent Pinterest-data store is configured on this website. For provider-held data, use that provider's privacy controls or contact process.
  • For privacy questions about this project, see the support page. A dedicated private support email or privacy-request form has not yet been published; please do not place sensitive account details in public posts. This contact limitation should be resolved before broad public release of the integration.

9. Children

The printable learning resources are designed for adults to use with young children. The website and Pinterest integration are intended for parents, caregivers, homeschoolers, teachers, and other adult educators; they are not designed to collect personal information directly from children.

10. Third-party services

Pinterest, GitHub Pages, and any authorization/integration provider operate under their own terms and privacy policies. The existing product listing is hosted by Ko-fi, which applies its own terms if you visit or purchase there. This policy does not replace those providers' notices.

11. Changes

This policy will be updated if the integration's permissions, storage, data use, contact method, or functionality materially changes. The date at the top will be revised when material changes are published.
